# DSPhotoStationFixer

A lightweight, autonomous shell script for **Synology DiskStations** (DSM 7.2.2+, DSM 7.x, DSM 6) to detect and regenerate missing or failed thumbnails (`@eaDir`) for **Synology Photos**, **Photo Station**, and **File Station**.

<a name="-english"></a>
## 🇬🇧 English

### 📌 Why this script is needed

On Synology NAS systems, media files in **Synology Photos** or **Photo Station** frequently end up with missing thumbnails (showing grey placeholders or infinite loading spinners):

1. **Removal of server-side codecs in DSM 7.2.2+**: Starting with DSM 7.2.2, Synology deprecated server-side transcoding/muxing for **HEVC (H.265)** and **HEIC**. Photos and videos uploaded via SMB network shares, rsync, or automated backups never get thumbnails generated by the NAS.
2. **Blocking `.fail` marker files**: When Synology's indexing daemon fails or encounters a format it cannot process, it writes 0-byte `.fail` markers into `@eaDir` (e.g. `SYNOPHOTO_THUMB_M.fail`). Once present, Synology **permanently abandons** all future indexing attempts for that file.
3. **Missing JPEG Muxer in Synology FFmpeg**: Synology's preinstalled `/usr/bin/ffmpeg` was built without the default `image2` muxer, failing on standard image extraction. This script resolves this by enforcing `-f mjpeg`.

---

### ✨ Features

* **Zero Dependencies**: Pure POSIX `/bin/sh` shell script. Runs natively on all Synology models and CPU architectures (x86_64, ARM, PowerPC).
* **Automatic Scan**: Scans videos (`.mp4`, `.mov`, `.mkv`, `.m4v`) and photos (`.jpg`, `.jpeg`, `.png`, `.heic`) for missing `SYNOPHOTO_THUMB_XL.jpg` or existing `.fail` markers.
* **Fast Skipping**: Intact files with existing thumbnails are checked in fractions of a millisecond and skipped, conserving CPU cycles.
* **Automatic Rotation**: Corrects smartphone video and photo orientation using EXIF and displaymatrix metadata (upright portrait mode).
* **Generates All Thumbnail Sizes**:
  * `SYNOPHOTO_THUMB_XL.jpg` (1280 px – lightbox & high-res preview)
  * `SYNOPHOTO_THUMB_B.jpg` (640 px – albums & DLNA)
  * `SYNOPHOTO_THUMB_M.jpg` (320 px – timeline & grid view)
  * `SYNOPHOTO_THUMB_S.jpg` (120 px – mobile list & square thumbnails)
  * `SYNOVIDEO_VIDEO_SCREENSHOT.jpg` (video player preview frame)
  * `SYNOFILE_THUMB_M.jpg` & `SYNOFILE_THUMB_S.jpg` (DSM File Station & DS File)
* **Cleans Stalled Indexing**: Removes blocking `.fail` marker files automatically.
* **Informative Logging**: Logs full paths with timestamps:
  ```text
  [21:03:15] [VID-REPAIRED] /volume1/photo/2024/Vacation/20240910_095045.mp4
  [21:03:22] [IMG-REPAIRED] /volume1/photo/mobile/Upload/IMG_2023.jpg
  ```
* **Concurrency Safe**: Uses `flock` to ensure scheduled runs never overlap.

### 🚀 Setup on Synology DSM (Task Scheduler)

Running the script via the **DSM Task Scheduler** is the recommended method. It runs autonomously in the background without needing a computer or SSH session open.

#### 1. Copy the script to the DiskStation

Upload `fix_syno_thumbnails.sh` (e.g. to `/volume1/photo/fix_syno_thumbnails.sh`) and make it executable:

```bash
chmod +x /volume1/photo/fix_syno_thumbnails.sh
```

#### 2. Create a Scheduled Task in DSM

1. Open DSM in your web browser.
2. Navigate to **Control Panel** ➔ **Task Scheduler**.
3. Click **Create** ➔ **Scheduled Task** ➔ **User-defined script**.
4. Configure the task:
   * **General Tab:**
     * Task: `Repair Thumbnails`
     * User: `root` *(required for write permissions in `@eaDir`)*
     * Enabled: Checked
   * **Schedule Tab:**
     * Set your desired frequency (e.g. Daily at 03:00 AM or Weekly)
   * **Task Settings Tab:**
     * User-defined script:
       ```bash
       /volume1/photo/fix_syno_thumbnails.sh /volume1/photo >> /volume1/photo/thumbnail_fix.log 2>&1
       ```
5. Click **OK** to save.

---

### 🕹️ Manual Control (Start, Stop & Monitoring)

#### Start Manually
* **Via DSM Web UI**: Select the task in Task Scheduler and click **Run**.
* **Via SSH**:
  ```bash
  nohup /volume1/photo/fix_syno_thumbnails.sh /volume1/photo >> /volume1/photo/thumbnail_fix.log 2>&1 &
  ```

#### Stop Manually
To terminate a running repair pass:
* **Via SSH**:
  ```bash
  pkill -f fix_syno_thumbnails.sh
  ```
* *Note:* Because every thumbnail is saved immediately upon creation, terminating the script will not corrupt or lose already repaired files.

#### Live Log Monitoring
To follow the progress in real time:
```bash
tail -f /volume1/photo/thumbnail_fix.log
```
*(Press `Ctrl + C` to exit the live log; the background process continues).*

### ❓ FAQ

#### Why can't I see `@eaDir` folders in Windows Explorer?
Synology's Samba configuration explicitly hides system directories beginning with `@` from network browsing (`readdir`). The directories exist on the filesystem and can be accessed directly by typing their full path.

#### Which FFmpeg version is used?
The script automatically searches for the best available binary:
1. `FFmpeg 7` (SynoCommunity package, if installed)
2. `CodecPack / Advanced Media Extensions` (`ffmpeg33`, `ffmpeg41`, `ffmpeg27`)
3. Built-in system FFmpeg (`/usr/bin/ffmpeg`)

It explicitly enforces `-f mjpeg` output, ensuring compatibility even on older architectures (ARM, PowerPC, x86).

## 🇩🇪 Deutsch

### 📌 Warum dieses Skript gebraucht wird

Auf Synology DiskStations bleiben in der **Synology Photos**-App oder **Photo Station** oft Mediendateien ohne Vorschaubild (graue Kacheln oder Ladesymbole):

1. **Wegfall serverseitiger Codecs in DSM 7.2.2+**: Synology hat ab Version 7.2.2 die serverseitige Unterstützung für **HEVC (H.265)** und **HEIC** gestrichen. Fotos und Videos, die per SMB-Netzlaufwerk oder Backup hochgeladen werden, erhalten vom NAS keine automatischen Thumbnails mehr.
2. **Blockierende `.fail`-Dateien**: Bricht der Synology-eigene Indizierungsdienst einmal ab, legt er im Ordner `@eaDir` 0-Byte-Dateien mit der Endung `.fail` ab (z. B. `SYNOPHOTO_THUMB_M.fail`). Solange diese existieren, unternimmt Synology **keine weiteren Versuche**, Vorschaubilder zu generieren.
3. **JPEG-Muxer-Einschränkung in Synology FFmpeg**: Das mitgelieferte System-FFmpeg auf Synology-Systemen wurde ohne standardmäßigen `image2`-Muxer kompiliert. Dieses Skript umgeht das Problem durch die explizite Nutzung von `-f mjpeg`.

---

### ✨ Was das Skript macht

* **Vollautomatische Erkennung**: Findet alle Videos (`.mp4`, `.mov`, `.mkv`, `.m4v`) und Fotos (`.jpg`, `.jpeg`, `.png`, `.heic`), bei denen das Haupt-Thumbnail (`SYNOPHOTO_THUMB_XL.jpg`) fehlt oder eine `.fail`-Datei vorhanden ist.
* **Intelligentes Überspringen**: Dateien mit bereits intakten Thumbnails werden blitzschnell übersprungen, ohne Rechenleistung zu verschwenden.
* **Auto-Korrektur der Drehung**: Liest die EXIF- und Displaymatrix-Ausrichtung (z. B. Smartphone-Videos im Hochformat) aus und richtet Thumbnails automatisch aufrecht aus.
* **Erzeugung aller Formate**:
  * `SYNOPHOTO_THUMB_XL.jpg` (1280 px – Vollbild-Lightbox)
  * `SYNOPHOTO_THUMB_B.jpg` (640 px – DLNA / Albumansicht)
  * `SYNOPHOTO_THUMB_M.jpg` (320 px – Raster- und Zeitleistenansicht)
  * `SYNOPHOTO_THUMB_S.jpg` (120 px – Mobile Listen)
  * `SYNOVIDEO_VIDEO_SCREENSHOT.jpg` (Standbild für Videoplayer)
  * `SYNOFILE_THUMB_M.jpg` & `SYNOFILE_THUMB_S.jpg` (DSM File Station / DS File)
* **Entfernung von Altlasten**: Bereinigt blockierende `.fail`-Dateien.
* **Transparente Protokollierung**: Schreibt saubere Logs mit Zeitstempel und vollständigem Pfad:
  ```text
  [21:03:15] [VID-REPAIRED] /volume1/photo/2024/Urlaub/20240910_095045.mp4
  [21:03:22] [IMG-REPAIRED] /volume1/photo/Camera/IMG_2023.jpg
  ```
* **Kollisionsschutz**: Verhindert mittels Lockfile (`flock`), dass parallele Durchläufe kollidieren.

### ❓ Häufige Fragen (FAQ)

#### Warum sehe ich `@eaDir`-Ordner unter Windows nicht?
Synology blendet Systemordner, die mit `@` beginnen, im SMB-Dienst standardmäßig aus der Verzeichnisauflistung (`readdir`) aus. Die Ordner sind jedoch physisch vorhanden und über direkte Pfadangaben sowie auf Dateisystemebene voll ansprechbar.

#### Welche FFmpeg-Version wird genutzt?
Das Skript sucht automatisch nach dem besten verfügbaren Binary auf dem NAS:
1. `FFmpeg 7` (SynoCommunity-Paket, falls installiert)
2. `CodecPack / Advanced Media Extensions` (`ffmpeg33`, `ffmpeg41`, `ffmpeg27`)
3. System-FFmpeg (`/usr/bin/ffmpeg`)

Es erzwingt bei der Ausgabe das Format `-f mjpeg`, wodurch auch ältere oder restriktiv kompilierte Synology-Builds (z. B. auf PowerPC-, ARM- oder x86-Modellen) zuverlässig JPEGs erzeugen können.
